## 1. 产品判断与两版差异

**定位不变**：本地、单用户、离线优先的个人管理工具。在线协作、云同步、重型修图、发布平台接入不在范围内。

**双面判断（本版新增的核心立场）**：应用必须同时服务两件事，缺一不可。

- 面向未来：**行动队列**——下一步做什么、**在等什么**、别漏带。
- 面向过去：**作品履历**——我出过什么、花了多少、和谁一起做的。

个人爱好类工具靠回顾面续命；只有待办的清空之日就是卸载之日。v1 把时间轴降级为"首页最近记录"，本版恢复为独立的履历面（第 4.9、4.11 节）。

**一次成功的使用 = 用户知道当前进展、能找到下一步、在上下文中完成操作、相关数据同步反映同一次变更、返回时保留原来的位置。**

与 v1 的差异：

| 议题 | v1 | v2 |
|---|---|---|
| 一级导航 | 首页/计划/日程/衣柜/相册 | 采纳（设置入口从根页齿轮进，v1 悬空处补齐） |
| 首页 | 6 区块总览 | 3 区块，一屏（4.1） |
| 准备状态 | 完成 / 未完成 | 三态，**在途是一级概念**（第 7 章） |
| 相册 | 7 个状态同级视图 | 两个模式（按场次 / 待处理）+ 状态当筛选（4.7） |
| 回顾面 | 时间轴并入首页 | 独立：角色履历 + 作品卡（4.9、4.11） |
| 当天 | 无 | **活动详情的「今天模式」**（第 6 章） |
| 资料收集 | 无 | **收录原语 + 收录箱**（第 5 章） |
| 账号 / 大屏 | 视情况收窄 | 直接收窄：账号暂缓、大屏不承诺（第 12 章） |
| 口径 / 失败恢复 / 诚实约束 | 有 | 全部保留，优先级提到最前（第 8、9 章） |

## 3. 核心：数据与关联如何串起来

这一章是全文的重点。数据实体有 13 类、关联成网，靠"多写几个页面"是串不起来的，只能靠三条机制。

### 3.1 关联全景

```text
角色 ─1:N─ 版本 ─1:N─ 计划 ─1:N─ 准备分类 ─1:N─ 准备任务
                        │
                        ├─1:N─ 打包项 ──── N:1 ───┐
                        ├─1:N─ 照片 ─1:N─ 照片版本 │
                        ├─1:N─ 参考图              ├── 装备（共享实体）
                        ├─1:N─ 团队成员            │    └─N:M─ 计划（project_assets）
                        ├─1:N─ 花费 ──────────────┘
                        └─1:N─ 计划日志

活动 ─1:N─ 计划                    ← 计划至多一个活动（CosProject.eventId 单值）
收录 ──scope──> 活动 | 计划 | 角色 | 装备 | 全局
```

要点（均为现有实现，不改）：

- 计划与活动是**多对一**：`Entities.ets:65`、`Schema.ets:5`；活动详情反向列出本场计划（`EventDetailPage.ets:134,147`）。
- 装备是**共享实体**：`Schema.ets:7` `project_assets(project_id, asset_id)` 组合主键，同一装备可被多个计划关联；改装备状态影响所有关联计划。
- 照片**必定属于一个计划**（`PhotoAsset.projectId`），无归属照片池不存在，本版不建立。
- 日志（`DiaryEntry`，`Entities.ets:134`）只属于计划。

### 3.2 三个轴：一级导航为什么是这五个

用户脑子里只有三个问题，一级入口按它们组织，不按数据表组织：

| 轴 | 用户问题 | 入口 |
|---|---|---|
| 时间轴 | 什么时候、接下来做什么 | 首页、日程（+ 今天模式） |
| 主体轴 | 这件事/这个人进行到哪 | 计划（+ 角色库） |
| 资源轴 | 我有什么、东西在哪、资料存哪 | 衣柜、相册（+ 收录箱） |

| 入口 | 默认内容 | 常驻业务入口 | 主要动作 |
|---|---|---|---|
| 首页 | 接下来 / 在途与待办 / 最近 | 全部待办、花费统计、收录箱、角色库 | 新建计划；快捷记一笔 |
| 计划 | 进行中计划 | 角色库、已完成、归档 | 新建计划 |
| 日程 | 按「今天 / 即将到来 / 日期待定 / 已结束」分组，可切月历 | 今天、日期待定、活动类型筛选 | 添加活动 |
| 衣柜 | 装备列表，支持分类/状态/位置筛选 | 查看被哪些计划使用 | 添加装备 |
| 相册 | 按场次组织的照片 | 待处理队列、作品集、归档 | 导入照片 |

**设置与数据**（账号、外观、主题、材质、触觉、备份、更新日志、隐私正文、示例数据、帮助）不是一级入口，由**各根页右上角齿轮**进入同一目的地（`pages/more/SettingsPage.ets`）。未登录与已登录入口一致，业务操作不放进账户菜单。

角色库以文字入口出现在**计划页首部**，同时进入首页业务入口区与全局搜索。花费统计以完整文字常驻**首页财务行**与统计页。

### 3.3 归属表：一个实体只有一个家

这是 H3 的落地表。**"家"= 唯一可编辑该实体的目的地**。

| 实体 | 家（唯一可编辑） | 别处的允许形态 |
|---|---|---|
| 角色 / 版本 | 角色详情 `pages/detail/CharacterDetailPage.ets` | 计划卡一行、履历、当天"人"、搜索结果 |
| 计划 | 计划详情/工作台 `pages/detail/ProjectDetailPage.ets` | 首页近期计划、日程本场计划、角色履历、待办行 |
| 活动 | 活动详情 `pages/detail/EventDetailPage.ets`（含今天模式） | 首页"接下来"、计划概览一行 |
| 装备 | 装备详情 `pages/detail/AssetDetailPage.ets` | 准备/打包行、衣柜列表、当天"出发前" |
| 照片 | 相册（由 `pages/main/LibraryPage.ets` 的照片分支拆出，成为独立一级入口） | 计划的照片视图（同一查询）、当天"收尾" |
| 参考图 | 计划/角色的参考区 `component/ReferenceGallery.ets` | 不出现于其他任何位置 |
| 团队 | 计划详情的团队区 | 当天"人" |
| 花费 | 计划概览 / 花费明细 `pages/more/ExpenseSummaryPage.ets` | 首页财务行、统计页 |
| 日志 | 计划详情的记录区 | 角色履历 |
| 收录 | 收录箱（未归位）/ 归属对象页（已归位） | 当天"凭证" |
| 拍摄清单 | 计划详情的照片视图 | 当天"今天要做" |

### 3.4 反向链接：每个家必须回答"谁指向我"

H5 的落地表。缺一条即为未完成：

| 家 | 必须显示的关联 |
|---|---|
| 角色详情 | 历次计划（时间倒序）+ 每个计划的场次、成片数、花费 |
| 计划详情（概览） | 角色与版本、活动（含"日期来自活动"标注）、装备与可用问题、团队成员、花费与预算、参考图 |
| 活动详情 | 本场计划（已有）+ 收录（票/图/链接） |
| 装备详情 | 被哪些计划使用；状态异常时说明影响范围 |
| 相册（按场次） | 场次/计划、成片数、归档 |
| 收录条目 | 归到哪个对象；未归位时引导归位 |
| 花费明细 | 范围（时间/计划/分类）与来源筛选 |

### 3.5 路由参数规范

H4 的核心。所有参数为运行时状态，不持久化（**禁止把导航状态写成业务字段**）。

| 目的地 | 路由参数 | 默认视图 | 返回恢复点 |
|---|---|---|---|
| 计划详情 | `ProjectRoute { id, section, focusTaskId?, outing, sheetKind }`，`section` = 0 概览 / 1 准备 / 2 打包 / 3 照片 | 从列表进 → 概览；从待办/打包/照片入口进 → 对应 section | 保留 section、Tab、筛选、滚动位置 |
| 活动详情 | `EventRoute { id, dayMode }` | 从日程进 → 详情模式；从底条/首页卡片进 → 今天模式 | 保留来源；今天模式返回后底条仍在 |
| 角色详情 | `CharacterRoute { id, section }` = 0 资料 / 1 履历 / 2 参考图 | 资料 | 保留 section |
| 装备详情 | `AssetRoute { id, from: 'wardrobe'\|'project'\|'day', projectId? }` | 资料 | 返回来源页对应位置 |
| 照片查看 | `PhotoViewerRoute { id, from, filterContext }` | 原图 | **回到原缩略图位置**（新增要求） |
| 相册 | `AlbumRoute { mode: 'byPlan'\|'queue', planId?, status? }` | byPlan | 保留 mode 与筛选 |
| 完整待办 | `TaskRoute { category, projectId?, range?, focusId? }` | 需要行动 | 保留筛选 |
| 花费/统计 | `LedgerRoute { projectId?, range?, category? }` | 本月 | 保留筛选 |
| 收录箱 | `InboxRoute { kind?, scope?, untriagedOnly? }` | 未归位 | 保留筛选 |

现有实现基础：`model/ProjectRoute.ets:3-10` 已有 `id / section / outing / sheetKind / preparing / linking`；本版只做两处改动——`section` 索引重排（新增概览为 0，原准备/打包/照片顺延为 1/2/3，所有调用点同步更新，无数据迁移），以及活动详情新增 `dayMode`。

### 3.6 视图可以多处，家只能一个

区分两件事，这是避免"重复"抱怨的关键：

- **允许**：同一数据的**筛选视图**在多处出现——相册"按场次"、计划的照片视图、作品集，三者都指向同一份查询，不是三份数据。
- **禁止**：同一对象的**完整编辑表单**在多处出现。属性编辑只在家里。

判断方法：如果两处都能改同一个字段，就违反 H3。

### 3.7 深度与出口预算

- 根页核心新增不藏菜单；首页高优先级待办**一次点击到达精确对象**（计划详情的对应 section + 焦点项）。
- 普通功能 ≤2 次入口选择，最多 3 次；表单填写与系统 Picker 不计入。
- 底部导航稳定；返回保留 Tab、搜索、筛选与滚动。
- 删除对象后只移除已失效的路由，**不能因为删除一份计划就清空全部返回上下文**（现 `Dashboard.ets:109-112,148-154` 的 pop 逻辑要按此收紧）。

### 3.8 页面内布局：分段优先

**一个页面承载多于一类内容家族时，用标题栏分段切换（`component/HdsTitleBarSegment.ets`），不把所有区块从上到下排成一条长列表。**

| 规则 | 说明 |
|---|---|
| 分段数量 | 2–4 个；超过 4 个说明该用筛选控件 |
| 分段承担什么 | **视图**（内容家族，或成员固定且封闭的列表状态，如"进行中/已完成/全部"） |
| 筛选承担什么 | 可组合的条件（日期、分类、角色、状态），用筛选控件/下拉，不占分段 |
| 段内首屏 | 每段首屏必须给出自己的关键结论，不能"点进去先滚动" |
| 状态归属 | 分段索引是**页面局部运行时状态**，不持久化（不写成业务字段） |
| 例外 | 首页（一屏三块必须同时可见）、今天模式的标题区（底线信息） |
| 反例警告 | 内容短、家族只有一个的页面**不分段**；不为分段而分段 |

各页面分段设计（实施清单）：

| 页面 | 分段 |
|---|---|
| 计划详情 | 概览 / 准备 / 打包 / 照片 |
| 活动详情（平时） | 概览 / 本场计划 / 收录 / 提醒 |
| 活动详情（今天模式） | 出发前 / 现场（标题区常驻，见第 6 章） |
| 角色详情 | 资料 / 履历 / 参考图 |
| 装备详情 | 资料 / 使用计划（内容短时退化为单列，不分段） |
| 相册 | 按场次 / 待处理 |
| 计划列表 | 进行中 / 已完成 / 全部 |
| 首页 | 不分段（一屏三块） |

## 4. 页面规格

### 4.1 首页：一屏三块

顺序固定，不随数据增删区块：

1. **接下来**——最近一场活动/计划的封面 + 倒计时 + **卡点**（在途里最需要关注的一项）+ 主动作。
2. **在途与待办**——**在途在前**，其后是逾期/今天/近期；合起来至多 5 条；行尾「全部待办 N 项」进入完整待办页。
3. **最近**——上一次场次的作品卡 + 两个快捷动作（记一笔、收录一条）。

规则：

- 新用户只显示一块首次启动引导与真正能做的入口，不用零值统计和空卡占满页面。
- 不做 KPI 行、不做常驻财务区块；花费以一行文字进入统计页。
- 「需要处理」摘要为逾期/今天/未来七天；无日期任务进「未定期」，**不会被错误归入逾期**；在途不进"需要处理"。
- 首页允许直接勾选低风险准备任务，成功后显示完成反馈与短时撤销（成本见 9.4）；失败保留条目与上下文。
- 处理后条目稳定退出，不突然重排整页。
- 近期计划最多 3 份，含名称、角色版本、有效日期、准备完成数、最需要处理的一项；无日期显示「日期待定」；不强制选"当前计划"。
- 当天若有活动，另显示一行**今天入口卡片**（第 6 章）。

### 4.2 完整待办页

- 分类「准备 / 打包 / 照片 / **在途**」+ 计划筛选 + 日期范围；默认显示需要行动的未完成项。
- 每行显示类别、所属计划、日期、动作；点击直达精确对象（`TaskRoute.focusId`）。
- 与首页摘要**共用同一套聚合**（第 7、8 章）。
- 「某计划待选 32 张」是**一条**照片事项，不能统计成 32 项准备任务。

### 4.3 计划列表

- 默认进行中，可切「进行中 / 已完成 / 全部」；归档在状态筛选中可达；日期待定是**日期维度**，不与已完成混为互斥状态。
- 卡片优先级：名称与角色 → 日期与阶段 → 准备完成数 → 下一项任务/装备问题/卡点。
- 进度只保留完成数；进度条仅在任务数 > 8 时出现（6 项任务显示 17% 是噪声）。
- 装备与打包摘要只在确有内容时出现。
- **不批量改写 `ProjectStatus`**；UI 可按筹划/准备/执行/后期/完成/归档组织，详细状态保留可见。准备任务全完成不自动改状态；计划结束不自动把照片标为成片。

### 4.4 计划工作台：概览 / 准备 / 打包 / 照片

进入规则必须可预测：新建保存后进准备；从列表进概览或该计划上次视图；从待办/打包/选片入口进明确视图与筛选。

| 视图 | 主要内容 | 就地动作 | 首屏要求 |
|---|---|---|---|
| 概览 | 日期/活动、任务摘要、**卡点区**（在途优先）、装备问题、预算摘要、团队与参考图摘要 | 改日期、关联活动、记一笔、编辑分工、添加参考图 | 看见下一步与卡点；团队与花费入口无需滚到底部 |
| 准备 | 分类任务、截止日期、在途标记、关联装备 | 勾选/编辑、补入模板、新建/复用装备 | 完成数与未完成可见；已完成可收起 |
| 打包 | 携带物、装备位置、已装包/未装包、出门模式 | 确认装包、添加物品、补入常用物品 | 未装包优先，触控充足，勾选后位置稳定 |
| 照片 | 本计划照片 + 状态筛选 + **拍摄清单** | 导入、选择、批量改状态、查看原图 | 当前计划与筛选明确 |

- 概览是摘要与入口，**不重复展示所有任务/装备/花费**。
- 准备进度、装备可用、装包确认**独立保存**，不合成为一个无解释的总完成率；三者各自无数据时显示「尚未添加任务 / 尚未关联装备 / 尚未建立清单」。

### 4.5 日程

- 默认列表按「今天 / 即将到来 / 日期待定 / 已结束」分组，可切月历；跨日活动在持续日期内均可找到，**多日活动不因开始日期过去就显示为已结束**。
- 列表与日历共用日期选择；日历显示当日活动与任务截止项，任务与活动用文字/标记区分；勾选日历中的任务**不创建**系统活动。
- 未定日期活动有稳定入口，不消失在空日历里。
- 活动详情按 **概览 / 本场计划 / 收录 / 提醒** 四段组织（3.8），不把通知设置、设备日历说明、计划列表、关联入口全部纵向堆叠（现 `pages/detail/EventDetailPage.ets` 即为此形态）。第一段给出类型、日期时间、地点、门票状态；「本场计划」已有实现（`EventDetailPage.ets:134`）；「提醒」段分别表达"用户选择了提醒 / 系统提醒已建立 / 权限或发布失败 / 提醒时间已过"，设备日历入口明确为「添加到系统日历」。编辑与删除进标题菜单，不占分段。
- 新建计划自动带入当前活动；活动与任务仍是不同对象。

### 4.6 衣柜

- 装备列表提供搜索、类型、状态、位置筛选；主要字段为名称、状态、位置与使用计划；价格是次要资料。
- 装备详情按 **资料 / 使用计划** 分段（3.8），支持从衣柜选择计划加入、从计划复用装备；新建装备可带入当前计划。内容过短时退化为单列。
- 待收货（Ordered）、维修、借出仍可记录或关联，但**显示实际状态并参与"在途"聚合**，不能伪装成可用。
- 解除计划关联与删除装备用不同措辞；删除说明全部关联影响与打包项处理；确认正文数量来自真实数据。
- 位置为空显示「未记录位置」并可补充，不生成虚构位置。
- 首版不增加借出归还日期、库存数量、制作订单。

### 4.7 相册与作品集

**顶层两个模式**（不把状态做成同级视图）：

| 模式 | 内容 | 回答的问题 |
|---|---|---|
| 按场次 | 每个场次/计划的封面 + 各阶段数量 | "整理哪一场" |
| 待处理 | 跨计划的待选/待修队列 | "还有什么没处理" |

状态（待选/已选/待修/已修/成片/已发布/归档）作为**筛选**，映射见 8.4。作品集是成片/已发布集合的**展示方式**，不维护重复副本。

- 导入前明确所属计划；从计划进入时带入；全局进入先选计划，可就地新建后继续；**不建立无归属照片池**。取消 Picker 安静返回，不显示「已导入 0 张」。
- 导入过程显示处理数量；结果区分成功/跳过重复/失败；已成功部分保留，失败可重试，**重试不得重复添加已成功项**。相同来源 URI 识别只是当前策略，不承诺跨来源内容去重。
- 批量模式显示已选 N 张，按钮写具体动作（如「标为待修」）；全选只作用于当前筛选，改筛选即清空选择并告知；提交期间锁定选择集合；成功后刷新计数并保留筛选，失败保留选择允许重试。
- 原图查看、说明编辑、状态变更、封面设置使用清楚动作。加载中、缩略图失败、原图缺失、元数据恢复后媒体缺失**分别表达**；支持重新导入到既有记录的修复流程。

见第 5 章。

### 4.9 角色与履历

- 角色库展示名称、作品、版本、关联计划；支持搜索、收藏（★，`CharacterDetailPage.ets:53` 已有）与新建。
- 角色详情用标题栏分段：**资料 / 履历 / 参考图**（3.8），不用一条长列表；主动作「用这个角色新建计划」常驻标题区。
- **履历**：该角色的历次计划，时间倒序，每条含场次、日期、成片数、花费、团队署名。这是"回顾面"的主要落点。
- 角色详情提供「用这个角色新建计划」，保持版本上下文。
- 角色是可复用资料，计划是一段具体准备过程，文案不混称"角色计划"。
- 参考图保持原归属；用于视觉准备的参考图**不进入成果照片计数**；封面操作说明作用对象。

### 4.10 花费与数据中心

- 首页财务行显示明确时间范围（如"本月已记录支出"）；计划概览显示实际支出与预算。
- 统计页默认本月，支持本年、自定义范围、计划、分类；进入时显式带入并显示来源筛选。
- 顺序：范围控件 → 已记录支出/预算关系 → 分类条形图 → 可点击明细；图表与明细用同一数据集合。
- 「记一笔」从计划中进入自动选中该计划；从全局进入要求显式选择，**不默认为数组第一份计划**。服装资料价格不自动生成支出。

- 照片数据按当前处理状态统计；`createdAt` 只能支持导入时间维度，**不能冒充拍摄日期或成片完成日期**；没有完成时间字段就不展示"本月完成了 N 份计划"这类趋势。
- 复用价值说明（诚实口径，不计入支出）：「本次复用 N 件装备（原值 ¥X，未计入支出）」。

- 出现在：计划详情的完成状态、角色履历、首页"最近"。

### 4.12 设置与数据

- 持续显示存储范围、照片副本说明、最近一次成功导出记录。
- 元数据导出明确不含照片；**不得将已注册 BackupExtension 显示为「已安全备份」**。
- 恢复流程：选择文件 → 校验 → 显示对象数量、版本、替换范围与媒体限制 → 提供先导出当前数据 → 最终替换确认 → 事务恢复 → 结果摘要；错误文件在替换前拒绝；替换失败保持原记录；**首版不声称合并恢复**。
- 应用被中断后重开可恢复到有效页面，展示未完成操作的真实结果，不重放已提交的新增请求。

## 5. 收录：一个原语

### 5.1 为什么是原语

`CosEvent` 只有单值 `url`（`Entities.ets:109`）。一次漫展现实里会有官网、票务订单、摊位表、展区图、返图相册、摄影师主页——加 `url2/url3` 不可持续。正确做法是加**一个多值附件原语**（H2）。

### 5.2 表结构

```sql
CREATE TABLE entries (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,                 -- link | ticket | map | note | idea | image
  scope_kind TEXT NOT NULL,           -- global | event | project | character | asset
  scope_id TEXT NOT NULL DEFAULT '',
  title TEXT NOT NULL DEFAULT '',
  url TEXT NOT NULL DEFAULT '',
  text TEXT NOT NULL DEFAULT '',
  local_path TEXT NOT NULL DEFAULT '',      -- 离线可看：图片存沙箱
  thumbnail_path TEXT NOT NULL DEFAULT '',
  pinned INTEGER NOT NULL DEFAULT 0 CHECK(pinned IN (0,1)),
  created_at INTEGER NOT NULL
);
CREATE INDEX entries_scope_idx ON entries(scope_kind, scope_id);
```

- 迁移：Schema 追加建表 + `MetadataBackupRepository` 的 `TableSpec` 与数字字段列表（`pinned`）同步；备份版本递增并保持旧格式解析。
- 媒体复用 `MediaRepository` 与 `ManagedImage`；缩略图策略与照片一致。

### 5.3 边界（必须划清）

| 已有实体 | 边界 | 不合并的理由 |
|---|---|---|
| `ReferenceImage`（`Planning.ets:26`） | 用于**视觉准备**的材料（影响造型/封面判断） | 有封面与构图语义，流程不同 |
| `DiaryEntry`（`Entities.ets:134`） | **计划内**的时间序日志 | 日志是"发生了什么"，收录是"我存了什么" |
| `CosEvent.ticketPurchased` | 仍是"买了没"的布尔**待办状态** | 布尔=进度；收录=凭证。两者并存，各司其职 |
| 照片 `PhotoAsset` | 成果照片 | 收录不进入照片计数与状态流 |

### 5.4 收录箱

- **捕获 0 必填**（H9）：粘贴链接即存；写一句话即存；选一张图即存。
- **归位**是可选的第二步：归到活动/计划/角色/装备，或**转成**任务/花费/参考图。未归位计数必须在首页可见，否则收集箱会退化。
- 入口：首页"最近"区块的一行（**仅有未归位条目时出现**）+ 各归属页（活动详情的收录区）。
- 系统分享接收入口属后续增强（ROADMAP 已有"接收分享与导入预览"），单独估算。

## 6. 今天模式

不是新页面，是**活动详情的一个模式**（复用 `ProjectRoute.outing` 已验证的手法：同页放大触控、改文案、改动作，见 `ProjectDetailPage.ets:108,500,519,524`）。

### 6.1 入口与触发

| 项 | 规则 |
|---|---|
| 时间窗 | **前夜 20:00 → 活动结束日 23:59**（最需要它的时刻是出发前的晚上） |
| 入口 A | 底部条：底部 chrome 的一部分，**让整个 Tab 栏一起上移**，不做浮动覆盖（避免重现"末项避让""滚动后固定区域不动"两轮补丁） |
| 入口 B | 首页"接下来"区块的当天卡片 |
| 文案 | 两处都显示 `今天 · 某漫展`（前夜显示 `明天 · 某漫展`），不只是一个图标 |
| 关闭 | 记住 `(eventId, date)`，当天不再出现 |
| 多活动 | 同一天多活动只显示最紧迫的一个 + "还有 N 个" |
| 退场 | 结束日 23:59 后入口消失（**只作用于入口**，页面仍可从日程进入） |
| 跳转 | 从底部条点击时**切到「日程」Tab 并在其栈上打开今天模式**（事件只归日程管一家）；Tab 状态安全，各 Tab 根内容不销毁（`Dashboard.ets:58-66`） |

### 6.2 结构：常驻标题区 + 两个分段

**标题区常驻且不可关闭**（底线信息）：`今天 · 某漫展`（前夜为 `明天 · 某漫展`）+ 地点 + 时间 + 跨日第几天。右侧是当天主动作 **记**（记一笔 / 收录一条 / 传一张）——它是"随上下文变化的主动作"，不占模块。

标题区之下用**两个分段**（3.8），按当天的时间顺序切分：

| 段 | 回答的问题 | 内容家族 |
|---|---|---|
| **出发前**（在家） | 带什么、票在哪、谁同行 | 打包清单、凭证、人 |
| **现场**（到场） | 拍什么、几点、记什么 | 今天要做、今天要拍、时间线、收尾 |

三个动词贯穿两段：**勾**（打包确认）、**打开**（地图 / 票 / 原图）、**记**（一笔 / 一条 / 一张）。

### 6.3 模块与默认装配

段内由模块组成，按 `appearWhen` **自动装配**：

| 段 | 模块 | 内容 | `appearWhen` | 可关闭 |
|---|---|---|---|---|
| 出发前 | 出发前 | 打包清单 + 出门模式（放大触控） | 有关联计划 | 是 |
| 出发前 | 凭证 | 收录中的 ticket / map / link（缩略图点开原图，**离线可看**） | 该活动有对应收录 | 是 |
| 出发前 | 人 | 团队成员 + 一键复制联系方式 | 有计划带团队 | 是 |
| 现场 | 今天要做 | 关联计划 + 拍摄时间 | 有关联计划 | 是 |
| 现场 | 今天要拍 | 拍摄清单（7.4） | 该计划有拍摄清单条目 | 是 |
| 现场 | 时间线 | 活动时段 / 约拍时间 | 有 `startTime` 或拍摄时间 | 是 |
| 现场 | 收尾 | "今天结束了？"→ 提示导入照片 | 当天 18:00 后 | 是 |

- **默认自动装配**：页面长度天然等于当天的真实信息量，用户默认什么都不用配。
- 用户能做的是**段内模块的开关 + 排序**，不是从空板添加。理由：配置的代价必须落在有耐心的日子，配置的价值要落在没耐心的日子。
- 约束：模块只做"信息 + 就地动作"，**禁止跨模块重复渲染**（打包清单只出现在"出发前"段）；**分段固定、不参与配置**（两级配置会互相打架，也违反 H1 的精神）。
- 存储：Preferences 一行 JSON `{ moduleId: { enabled, order } }`，**不进业务数据库、不动备份版本**。
- 测试：模块 × 出现条件会组合爆炸，只测「全空 / 典型 / 全满」三种装配 × 两段；模块错误态复用通用三态（9.1）。

### 6.4 两种模式的差异

| | 活动详情（平时） | 今天模式 |
|---|---|---|
| 主要动词 | 编辑、关联计划、设提醒 | 勾、打开、记 |
| 编辑/删除 | 可见 | **隐藏**（人群里防误触） |
| 触控目标 | 常规 48vp | 放大 64vp（复用出门模式尺寸） |
| 首屏 | 活动信息 | 今天要带的 + 凭证 |
| 跨日 | 正常显示 | 显示"第几天"，按 `endDate` 判定 |

## 7. 准备三态与在途

### 7.1 定义

| 状态 | 定义 | 聚合归属 |
|---|---|---|
| 待办 | 未完成、非在途 | 按日期进逾期/今天/近期/未定期 |
| **在途** | 未完成、且声明了等待对象或等待时间 | 独立分组；**不计逾期**；不进"需要处理" |
| 完成 | `done = true` | 已完成，可收起 |

### 7.2 为什么是在途

真实准备由等待构成：等快递、等毛娘排期、等妆娘试妆、等摄影师交片。把等待项混进"逾期"会造成警报疲劳，很快没人看。

装备状态的 `Ordered / Repair / Lent`（`Entities.ets:24-31`）已经是这个语义，本版把它上升到任务与计划层面。

### 7.3 实现

- 增量迁移：`preparation_tasks` 追加 `waiting_on TEXT NOT NULL DEFAULT ''`、`waiting_until TEXT NOT NULL DEFAULT ''`（空串 = 不在途）。
- v1 近似（不做迁移时的降级）：用「关联装备状态为 Ordered/Repair/Lent」+ 任务备注表达，聚合读同一规则。
- 计划概览的**卡点区**读同一份聚合：优先显示在途项及其等待对象。

### 7.4 拍摄清单

计划内的轻量列表（`title` + `done` + 可选参考图），**只在计划照片视图与今天模式出现，不计入准备进度**。

- 存储：`project_shots(id, project_id, title, done, sort_order, created_at)`。
- 它对应今天模式「现场」段的**今天要拍**模块，`appearWhen = 该计划有拍摄清单条目`——**不需要提前决定它是"核心"还是"可选"**，由数据决定显隐。

## 8. 数据口径与关联契约

### 8.1 口径表

| 数据 | 统一定义 | 特殊情况 |
|---|---|---|
| 准备进度 | 已完成准备任务 / 当前准备任务数 | 0 项显示"尚未添加"，不显示已完成；在途计入分母不计入分子 |
| 装备可用 | 满足当前可用规则的关联装备 / 关联装备数 | 展示待收货/维修/借出原因；不代替准备进度 |
| 打包进度 | 已确认装包 / 当前打包项 | 常用物品与装备条目保持原关系 |
| 逾期任务 | 未完成、有截止日期、早于本地今天、**非在途** | 无日期不逾期；完成/归档计划的准备事项排除 |
| 在途任务 | 未完成且 `waiting_on` 或 `waiting_until` 非空 | 不计逾期 |
| 即将到来的计划 | 显式目标日期，否则关联活动开始日期 | 标明日期来源；活动日期变更可预见地反映 |
| 实际支出 | 当前范围（时间/计划/分类）内 Expense 金额之和 | 单位为分；不计衣柜价格 |
| 预算 | 用户明确设置的计划预算 | 未设置、明确 0、历史未明确区分（见 8.3） |
| 照片处理 | 全部入口共享同一聚合映射（见 8.4） | 已修、成片、归档独立；参考图排除 |
| 完成计划 | 状态为 COMPLETED | 归档是否含完成需另有证据，不推定 |

### 8.2 聚合一次

所有摘要（首页、待办页、计划卡、计划概览、统计）读**同一个模型层对象**：

```text
PlanReadiness {
  prep:  { done, total, waiting, next }
  pack:  { packed, total }
  photos:{ byStage }
  money: { spentCents, budgetCents?, budgetConfigured }
  blockers: []        // 在途项、装备不可用、缺日期
}
```

页面不得各写一遍过滤（H6）。写入后首先刷新相关集合及其聚合依赖，不默认重读全部集合（13 个集合的全量 `refresh()` 见 `ApplicationState.ets:231-240`）。

### 8.3 预算兼容

`budgetCents` 默认 0，无法区分"未设置"与"零预算"（`Entities.ets:70`、`Schema.ets:5`），且当前无条件显示「预计预算 ¥0.00」（`ProjectDetailPage.ets:455`）。

- 新增可空 `budgetConfigured`：迁移时正数为已设置，历史零值为**未知**；新表单显式保存设置/未设置。
- 旧备份缺少标记时采用同样规则，不把全部旧零值推断为任意一侧。
- 汇总只对明确预算给出比较并显示覆盖计划数；不存在预算时不绘制耗用率。
- 若本轮不引入该字段，**暂时保守显示历史语义，不宣称已完成歧义修复**。

### 8.4 照片状态统一映射

| 阶段 | 状态值 | 统一视图名 |
|---|---|---|
| 导入 | IMPORTED / RAW | 待选 |
| 已选 | SELECTED | 已选 |
| 待修 | WAITING | 待修 |
| 已修 | RETOUCHED | 已修 |
| 成片 | FINAL / PUBLISHED | 成片 |
| 归档 | ARCHIVED | 归档 |

`PUBLISHED` 仅保留既有发布记录含义，不表示应用已接入发布平台。**本映射同时用于相册、计划、首页与统计。**

**可见计数变化（必须一并处理）**：

- 相册「成片」当前含 RETOUCHED（`Rules.ets:64`），统一后**不含** → 计数下降。
- 作品集「成片」当前只含 FINAL，统一后含 PUBLISHED → 计数上升；「已发布」是否仍为独立视图需明确（现为用户可见状态，`PhotoGrid.ets:43`）。
- 受影响的既有断言：`entry/src/test/LocalUnit.test.ets:53`（相册成片 count=3）、`entry/src/ohosTest/ets/test/UiPolish.test.ets:53`（作品集成片 = FINAL）——按新映射更新，并在变更记录中写明原因。

### 8.5 关联约束

- 计划**至多一个活动**（`CosProject.eventId` 单值，`Entities.ets:65`）。本版保持该约束；移动到另一活动时说明旧关联将被替换，不创建不存在的多活动能力。
- 装备是共享实体，修改状态影响所有关联计划，相关页显示受影响关系。
- 任务与参考图的归属校验继续由领域与仓库保护。

## 9. 状态、失败与诚实约束

### 9.1 状态矩阵

| 状态 | 展示 | 动作与数据行为 |
|---|---|---|
| 首次业务加载 | 骨架或明确加载提示 | 不闪现假空状态；设置等已就绪能力可用 |
| 真正无数据 | 一条原因说明 + **就地启动动作** | 不出现多组重复空卡 |
| 搜索/筛选无匹配 | 保留输入与筛选，显示无匹配 | 清除筛选/改关键词，不引导重复创建 |
| 保存中 | 原按钮显示具体动作进行中 | 防重复提交；只禁用会冲突的操作 |
| 保存失败 | 字段错误或当前页面持续错误条 | 保留表单、选择与滚动；可重试 |
| **数据已提交、页面刷新失败** | 提示记录已保存但显示未更新 | 重新加载，**不让用户重复提交同一笔数据** |
| 导入部分失败 | 分开显示成功/跳过/失败数量 | 保留成功项，失败可重选或重试 |
| 权限拒绝/系统能力失败 | 说明受影响的具体能力 | 核心本地记录可继续；提供手动操作/设置入口 |
| 对象已被删除 | 明确的不存在状态 | 返回最近有效页面，不渲染虚构的新对象 |
| 图片缺失 | 缺失原因与受影响数量 | 能修复归属匹配的既有记录或查看恢复说明 |
| 长操作 | 数量进度或不确定进度 | 可取消尚未提交部分；不承诺后台必定完成 |

### 9.2 不谎报成功

- 不做假撤销按钮：撤销必须真实保存旧值并处理对象失效。
- 不把已注册 BackupExtension 显示为「已安全备份」。
- 不显示「已导入 0 张」成功提示。
- 不承诺跨来源内容去重。
- 恢复是替换语义，就不声称合并恢复。
- 没有完成时间字段，就不展示完成趋势。
- 系统确认被取消时，不声称成功。

### 9.3 操作结果类型

`runOperation` 当前把写入与 refresh 放在同一 `try`（`ApplicationState.ets:249-258`），只返回布尔，无法区分写入失败与刷新失败，直接影响重试是否产生重复记录。

- 结果类型：`{ status: 'ok' | 'partial' | 'failed' | 'savedNotRefreshed', detail? }`。
- 保留串行写入保护（共享 `busy` 不取消）；细分操作状态：只有冲突操作被禁用，安全的只读浏览继续。
- 按依赖刷新：一次照片状态变更不重新查询全部角色/活动。

### 9.4 撤销的真实成本

两件事成本差一个量级，不能当一件事处理：

| 场景 | 回滚方式 | 结论 |
|---|---|---|
| 准备任务勾选 | 布尔取反（旧值可推导） | 可直接提供，成本低 |
| 照片批量状态变更 | 需保存逐张旧值 | 必须真实存储旧值；成本高 |

若照片批量撤销在本轮成本过高，改用"明确、可逆的状态修改路径"，**不得用假撤销按钮替代**。

### 9.5 删除与归档

- 计划结束优先提示归档；归档保留照片与历史数据。
- 真正删除显示对象名称、关联数量与文件影响；确认后提交。首版保留永久删除语义，**不显示无法兑现的回收站或删除撤销**。
- 若另行加入回收站，需要软删除、媒体保留与备份语义，单独估算。

### 9.6 表单与草稿

- 表单字段使用业务语言并就地报错；提交时定位首个错误，保留已输入内容；主提交动作只有一处。
- 键盘不遮住当前输入与提交操作；长表单随焦点滚动。
- 关闭未修改表单直接退出；有修改时提供「继续编辑 / 放弃修改」。
- 计划创建与较长业务表单提供**本地草稿**（现 `EditDraft` 为内存态，`Dashboard.ets:70,129`，需新增持久化），标明恢复时间；草稿不进入正式业务统计。
- 不在每次小字段编辑时弹出多余确认。

| B. 收录原语 | `entries` 表、仓库、收录箱页、归位流程、首页一行入口 | 粘贴/写一句/存一图 3 步内完成；未归位计数可见；旧备份兼容 |
| C. 活动详情的今天模式 | `EventRoute.dayMode`、标题区 + 两段、模块装配、底部条与首页卡片、触发时序 | 前夜与当天按规则出现；标题区常驻；分段固定、模块可开关且记住；退场只作用于入口；Tab 切换不丢位置 |
| D. 首页与待办 | 三区块首页、完整待办页、在途三态聚合、卡点区 | 一次点击到达精确对象；在途不计逾期；返回保留筛选与滚动；空状态均有就地动作 |
| E. 相册与衣柜 | 相册独立、两模式、词表统一、作品集复用同一查询 | 全局与计划计数一致；四套词表归一；受影响断言已更新 |
| F. 角色履历与作品卡 | 角色履历分栏、作品卡、首页"最近" | 履历含场次/成片数/花费/署名；作品卡复用 `ProjectShareObject` |
| G. 拍摄清单 | `project_shots`、计划照片视图、今天模式第 9 模块 | 不计入准备进度；`appearWhen` 生效 |
| H. 导航收口 | Tab 重命名（Cos→计划、活动→日程）、相册独立、我的拆解、设置入口 | 每个旧入口有可达替代；`ui-test`/`layout-test` 断言全部更新；**最后执行** |

依赖：A 的聚合口径是 D/E 的前置；B 是 C 的前置；E 的照片口径在 F 之前；H 只在前面阶段稳定后进行。

每阶段结束有可运行结果，单次交付围绕完整用户任务，不同时替换所有页面。迁移后的数据兼容与旧代码回退能力分开评估；不承诺简单切回旧版本能读取新的备份或字段。

优先级：P0 = 功能可发现、创建/准备/打包/选片/记账闭环、返回与草稿保护、正确口径、保存与导入失败恢复、数据兼容、恢复确认、真实能力说明、核心设备与无障碍可用。P1 = 扩展筛选、最近使用、真实大屏效率、大数据量性能。P2 = 回收站、多活动计划、采购/分期、云同步、在线协作、发布平台、复杂修图。

## 15. 验证与发布条件

### 15.1 可用性验证

**先测现状形成基线，再测原型与实现。** 招募 5 名目标用户（新用户、已有衣柜的复用用户、多计划/照片较多的用户），不先讲解入口，给真实目标，记录首次点击、完成情况、错误返回、寻找时间。

**前置条件（必须在阶段 B/C 之前解决）**：当前包使用**开发调试 Profile**，只适用于获授权设备——招 5 名 Coser 测试需要先在 AGC 授权设备或改用发行证书。这是排期里最容易漏掉的一项依赖。

只看三个场景，其他不看（前两个决定它有没有用，第三个决定它会不会被一直打开）：

| 场景 | 成功信号 | 失败信号 |
|---|---|---|
| 出展前夜打包 + 早上出门 | 找到未装包清单、找到票与地址、勾选可改回 | 把准备完成误认为装包；误点后无法恢复 |
| 拍摄后：导入 300 张 → 选 → 标待修 → 挑封面 | 理解所属计划与当前选择范围；导入失败不产生重复记录 | 全选作用范围不明；重复导入 |
| 三个月后回看"今年做了什么、花了多少" | 从角色履历或作品卡说清场次与花费 | 各处金额不一致；找不到回顾入口 |

核心任务至少 4/5 无指导完成；同一入口或状态被两人误解即进入修正。灾难性数据误操作、不可恢复丢失、错误成功反馈**不以平均完成率掩盖**。

### 15.2 工程验证

- 每工作包按风险运行一次正式构建和直接相关回归；规划/表单改动检查 UI 路径，聚合口径、事务、预算兼容与备份改动检查对应领域与隔离数据。
- **开发期默认只做基础确认**：`build.sh` 编译通过 + 按改动类型选择的 `test_schema.py` / `test_theme_colors.py`（不需设备）。设备套件（`device-test`、`ui-test`、`layout-test`、`settings-layout-test`、`theme-test`、`ui-polish-test`、`demo-test`）留到阶段收口或发布候选时按需选跑一个，不在每次改动后连续重跑。
- 复用 `scripts/`：`build.sh`、`test_schema.py`、`device-test.sh`、`ui-test.sh`、`layout-test.sh`、`settings-layout-test.sh`、`theme-test.sh`、`ui-polish-test.sh`、`demo-test.sh`。新增用例只覆盖新的关键行为与回归风险。
- Hypium 按 **Pass / Failure / Error** 判断，不把退出码或测试包编译等同于通过。
- 数据集至少覆盖空数据、典型使用与压力规模：建议起点 100 计划 / 1,000 装备 / 5,000 照片元数据（是测量起点，不是宣传容量）。
- 性能建议目标：普通点击约 100ms 内出现视觉反馈；典型数据常用页面切换 P95 约 300ms 内出现有用内容；本地普通保存 P95 约 500ms。统一设备、构建模式、数据量与冷热启动后才比较。
- 至少验证 API 23 与 API 26 的核心路径、深浅色、系统字体放大、读屏、键盘与安全区。设备不可用时记录未验证项，**不能将缺少证据写成通过**。

### 15.3 发布条件

**1.0 收口（与重构并行，互不阻塞）**

1. 若保留活动提醒承诺，补足真实授权、失败补救、后台投递与通知定位结果；否则去掉未验证承诺或收窄范围。
2. 账号入口按第 12 章暂缓，或解决 `1001502003` 并验证登录/退出；离线使用不受账号阻断。
3. 隐私正文、帮助、备份说明、截图与实际能力一致；云同步、多人协作、完整媒体备份只描述已交付能力。
4. 核对平台规则；本文不替代官方审核要求。

**1.x 重构**

5. 六条核心流程与数据恢复流程有明确结果、可用返回与错误处理；没有必须由开发者解释才能找到的主要入口。
6. 既有数据迁移与旧备份隔离恢复通过；不清空 `personal.db`。
7. 无已知数据丢失、错误替换、重复提交等阻断问题；失败不谎报成功。
8. 全局与计划视图的金额、准备、在途与照片口径一致；未设置信息有真实表达。
9. 声明支持的设备、版本与核心输入方式有对应证据；大字与读屏可完成核心任务。

## 16. 完成后的体验

用户从首页看见下一步与卡点，从计划完成具体工作，从日程安排时间，从衣柜找到并复用物品，从相册整理照片，从收录箱存放看到的一切。出展当天打开一处就能拿到地点、票、图和清单。角色、花费与数据管理有固定入口；同一记录在相关场景下出现，计数与状态始终一致。

三个月后打开它，能看见自己出过什么、花了多少、和谁一起做的。
