## 1. 一句话结论：最伤的 3 个观感问题

1. **很多页面像"半成品"**：空状态/零值页只有一张卡，往下 40%–60% 纯空白；同时 `0% / 0 个 / ¥0.00 / 0 B` 被当成主角摆在首屏（46、04、70、73、41、45 都能看到）。
2. **组件不像同一套设计系统**：Tab 图标 2 个面性 + 3 个线性（选中态也不统一）、标题栏 3 个无文字图标、卡片"描边 + 阴影"两套、详情页两种标题头 → 明显的拼装感。
3. **字号与信息层级失控**：首页同时出现 26fp 问候、10fp 说明、同一进度三种写法；大字号 2x 下设置页档位标签被拆成竖排单字、右侧文字被裁切，直接不可用。

### P0

#### P0-1 大字号（fontScale=2）下设置页档位文字竖排拆字、行结构塌陷、右侧文本被裁切
- **严重度**：P0 ｜ **确凿度**：确凿可见（测试台 378vp「手机」画布，且 `setFontSizeScale(2)`）
- **截图**：`docs/validation/settings-phone-large-font-api26.png`、`settings-narrow-large-font-api26.png`（10-07 13:42）
- **现象**：
  - 「关闭 / 灵动 / 硬朗」「流畅 / 轻柔 / 精美」「天蓝…跟随系统」「左手 / 智感握持 / 右手」的档位标签全部变成**一行一个字竖排**（"关闭"→"关"换"闭"，"跟随系统"→"跟随/系统"两行）；
  - 行内标签从"图标 + 左标签 + 右侧滑块"重排为"图标、标签居中换行到上方、滑块落下一行"，整页行高被撑到 500–600px；
  - 「清除缓存」行右侧「缓存文件总大小：0 B」+ 问号图标**被画布右边裁掉**（`…总大小：` 断在右缘）；用户名输入框被截成「RRA-」样式的残字。
- **推断原因**：档位标签被写死宽度——`SettingsChoiceSlider.ets:34` `labelWidth()` 返回 40/64vp，并在 `:69-87` 里 `fontSize(12)+width(40)+maxLines(2)`；2 字标签在 2x 字号（24vp/字）下 40vp 只放得下 1 个字。材质等级的手写标签 `SettingsPanel.ets`（`materialLevelLabel` 用 `.width(40)`，约 :565-590）同理；「清除缓存」行是 `Flex(SpaceBetween)` 左右两个无 `flexShrink/layoutWeight` 的文本，2x 时右段必然溢出（`SettingsPanel.ets` trashContent，约 :640-690）。
- **现状核验**：当前代码**仍是定宽 40/64 + maxLines(2)**，未随 fontScale 自适应 → 该缺陷大概率仍在（需真机 2x 复验）。
- **用户影响**：系统开大字号（系统设置里很常用，尤其长辈模式）后设置页不可读、不可操作，是硬性无障碍缺陷。
- **修法**：标签宽度改 `constraintSize({minWidth:40})` + 按 `measure` 或让 `Row` 均分；字少的两行内不要 `maxLines(2)`；整行改 `Flex({wrap:Wrap})`，字号 ≥1.5 时切换为"标签在上、控件在下"的两行布局；「清除缓存」右侧文本 `layoutWeight(1)+textAlign(End)`，帮助图标不参与压缩。
- **成本**：M

#### P0-2 标题栏玻璃材质下，滚动内容与标题/返回按钮重影叠压
- **严重度**：P0 ｜ **确凿度**：确凿可见（4 处不同页面/主题）｜ **属于材质设计还是 bug：待复核**
- **截图**：`.shots/33-settings-bottom.jpeg`、`.shots/44-system.jpeg`、`.shots/81-sky.jpeg`、`.shots/90-dark.jpeg`（设置页滚动中）；`docs/validation/settings-wide-api26.png` 右栏顶部同样被切
- **现象**：
  - 设置页向上滚动后，上一行（「用户名 / Ray」「华为账号」图标与两行说明）在标题栏区域被**模糊地完整透出**，与「设置」标题、返回圆钮直接叠在一起：`44-system.jpeg` 里「设置」正压在「华为账号」四个字上，`33` 里返回圆钮正好压住人物图标；
  - 最顶部状态栏区域还能看到被裁掉一半的「Elva Cos」字样与时间并排（`44`）；
  - `settings-wide` 右栏「设置」分组标题被上边缘切掉一半。
- **推断原因**：内容按 `ignoreLayoutSafeArea(TOP)` 滚到标题栏/状态栏之下，而 HDS 标题栏是半透明材质 + 弱模糊（`SystemCapability.titleBar(..., effects, materialLevel, ...)`，`Dashboard.ets:643-646`），没有随滚动加深的 scrim/不透明底。**推断**：材质等级为"轻柔/流畅"时模糊半径与底色不足以隔离正文。
- **现状核验**：当前外壳仍是同一套 HDS 标题栏 + ignoreLayoutSafeArea，**需复核材质参数**；若这是有意的沉浸效果，也至少需要加 scrim。
- **用户影响**：每次滚动设置/详情页都会看到文字互相叠压，是"看起来坏了"的直接来源，也是用户说"UI 糟糕"时最容易指认的地方。
- **修法**：给标题栏加随滚动进度 0→1 的底色 scrim（遮住正文）；或内容区顶部额外留出与标题栏等高的不透明渐变；材质等级 ≥轻柔 时提高 blur/scrim 强度；同步检查列表首行不要正好停在标题栏下方。
- **成本**：S（置底遮罩）/ M（滚动联动 scrim）

#### P0-3 空状态/零值页"上一张卡 + 下半屏空白"，首屏像未完成
- **严重度**：P0（新用户首屏） ｜ **确凿度**：确凿可见（4 页）｜ **CTA 缺失部分已被 10-08 代码修掉**
- **截图**：`.shots/46-events.jpeg`（漫展空态，内容止于 29% 高度）、`.shots/04-me.jpeg`（我的-作品集空态，止于 53%）、`.shots/70-project.jpeg`（项目空装备）、`.shots/73-character.jpeg`（角色详情）
- **现象**：
  - `46`：页面只有「和热爱见面」标题 + 一张空态卡（"下一场见面，值得期待 / 记录漫展日期…"），卡下方到 Tab 栏之间 **≈70% 屏幕纯白**，且旧版空态**没有按钮**；
  - `04`：统计卡 + 筛选行 + 空态卡后，**≈45% 空白**；
  - `70`：「本次装备 0 件」空态卡 + 一行「预计预算 ¥0.00 · 装备记录金额 ¥0.00」后到浮动操作栏之间 **≈35% 空白**；
  - 空态卡本身都不在屏幕视觉中心，而是紧贴页面内容流顶部。
- **推断原因**：空态用 `EmptyState` 直接塞进 `Scroll` 的普通流式布局（`EventsPage.ets:94-99`、`PhotoGrid.ets:158-161`、`ProjectDetailPage.ets:249-260`），没有 `layoutWeight(1)+justifyContent(Center)` 的居中容器；页面也没有"内容不足一屏时占满"的尾随策略。
- **现状核验**：活动/照片空态的 CTA 已在 10-08 补上（`EventsPage.ets:94-99`、`PhotoGrid.ets:158-161`），但**空态布局仍走内容流**，半屏空白与偏顶问题仍在；`PhotoGrid` 与 `MePage.ets:108` 的时间轴空态仍无按钮。
- **用户影响**：第一次打开「漫展/我的」看到的就是一张孤零零的卡 + 大片空白，直接形成"这 App 没做完"的判断。
- **修法**：抽一个 `EmptyStatePage`：内容不足一屏时垂直居中（`Column().layoutWeight(1).justifyContent(Center)`），图标/标题/说明/主按钮四件套；无数据但页面有筛选时，补"清除筛选"类次要动作；零值行整体隐藏。
- **成本**：S

### P1

#### P1-1 首页标题栏 3 个无文字图标，语义靠猜
- **严重度**：P1 ｜ **确凿度**：确凿可见 ｜ **与 Lead 笔记 A5 呼应**
- **截图**：`.shots/95-final.jpeg`、`93-light-restored.jpeg`、`91-dark-restart.jpeg`、`docs/validation/home-phone-restored-api26.png`
- **现象**：标题「首页」右侧横向 3 个同尺寸圆形描边按钮：加号、时钟、相册风景图；彼此等权、无文字、无分组，默认态下和标题几乎同高，占掉标题栏右侧近一半宽度。
- **推断原因**：首页 `rootTools(0)` 返回 3 个菜单项（新建计划 / 添加活动 / 导入照片，`Dashboard.ets:387-404`），HDS 菜单只渲染图标、label 进读屏不进视觉；图标分别是 add、clock（活动）、albums（照片）。
- **现状核验**：当前代码仍是 3 个图标菜单，**仍存在**。
- **用户影响**：时钟最容易被理解为"历史/闹钟/最近"；相册图标可能被理解为"相册浏览"而不是"导入照片"。新用户不敢点，等于浪费三个高频入口。
- **修法**：只保留「＋」一个主入口，展开成带文字的菜单（新建计划 / 添加活动 / 导入照片）；或把高频的"导入照片"下放到最近照片区。
- **成本**：S

#### P1-2 Tab 图标"2 面性 + 3 线性"，选中态与图标语义都不统一
- **严重度**：P1 ｜ **确凿度**：确凿可见（跨 Tab）｜ **与 Lead 笔记 A6 呼应**
- **截图**：`.shots/95-final.jpeg`（首页选中，面性窗口图标）、`72-cos-root.jpeg`（Cos 选中，面性笑脸）、`46-events.jpeg`（活动选中，线性时钟）、`04-me.jpeg`（我的选中，线性"人+声波"）、`73/70` 未选中态
- **现象**：5 个 Tab 中「首页」「Cos」选中/未选中都是**实心面性**图标，「活动」「衣柜」「我的」始终**线性**；Tab 栏里同时出现两种笔画语言。语义上：首页是"浏览器窗口"、活动是"时钟"、衣柜是"抽屉柜"、我的是"人+信号波"。
- **推断原因**：`Icons.ets:13-17` 直接混用系统资源：`return_home_fill`、`ohos_user_auth_icon_face`（面性）、`ohos_ic_public_clock`、`rectangle_filled_and_line_horizontal_and_rectangle`、`person_badge_waveform`（线性）。
- **现状核验**：**仍存在**（当前 `Icons.ets` 未改）。
- **用户影响**：最外层导航的图标风格没对齐，整屏观感立刻"廉价"；活动=时钟、我的=人物+声波的可理解性也弱。
- **修法**：一套图标语言二选一（建议线性 + 选中着色/底部短横）；业务语义重画：活动=日历、衣柜=衣架/柜、我的=人像；`Cos` 用角色剪影或面具。
- **成本**：M（换 5 个 SVG/PNG + 选中态规则）

#### P1-3 宽屏分栏：左列垂直居中、双列起点不齐、4:6 宽度与内容量不匹配
- **严重度**：P1 ｜ **确凿度**：截图可见（测试台 920vp 画布内确凿）｜ **与 Lead 笔记 A8 呼应**
- **截图**：`docs/validation/home-wide-start-api26.png`、`home-wide-bottom-api26.png`、`settings-wide-api26.png`
- **现象（仅画布内）**：左列（问候/花费统计/计划卡/两按钮）在半屏高度处**垂直居中悬浮**，起点比右列「下一场活动」低约 60px；右列从内容顶部开始独立滚动；左列内容只占约 40% 屏宽却放着短内容，右列 60% 挤着活动 + 待办 + 最近照片；两列之间的全高 1px 竖线把"左空右满"的失衡放大了。
- **推断原因**：`DashboardSplitLayout.ets:22-28` —— 左列 `Column{ Blank(overviewTop); Column(overview).layoutWeight(1).justifyContent(FlexAlign.Center) }` 明确垂直居中；`:21` Row space 16 + `:29` 全高 Divider；宽度 `layoutWeight(4)` vs `layoutWeight(6)`。
- **现状核验**：代码仍在，**生产宽屏（≥600vp）会以 896vp 全高放大这个错位**。
- **用户影响**：折叠屏/平板上首屏左半是"悬在半空的问候+卡片"，与右列完全不对齐，是宽屏用户第一眼的失分点。
- **修法**：左列改为顶部对齐（去掉 `justifyContent(Center)`，`Blank(overviewTop)` 与右列 `Blank(scrollTop)` 取同一值）；分栏比例按内容改为 5:5 或 6:4；分栏线在内容结束处收尾或直接去掉；左右列增加各自的滚动而不是只让右侧滚。
- **成本**：M

#### P1-4 五主题下"主按钮"极性翻转：蓝主题白字实心，绿/粉/橙/红变浅底深字
- **严重度**：P1 ｜ **确凿度**：确凿可见（同一张对照图）｜ **与 Lead 笔记 B18 呼应**
- **截图**：`docs/validation/theme-palettes-api26.png`（10-08，五主题浅/深控件参考）
- **现象**：同一位置「继续准备」按钮：蓝主题 = 饱和蓝底 + 白字；绿/粉/橙/红主题 = **浅色底 + 深字**；而左侧次要按钮同时又是浅蓝/浅色 tint，主次按钮在非蓝主题里几乎同色；浅色主题的"准备中"药丸（橙/粉）与底色同为同色系浅色，12vp 小字观感偏淡。
- **推断原因**：`ThemePalettes` 里非蓝主题的 `brand` 用了浅色、`onAccent` 用深色；蓝主题保留系统原生 `brand`，于是同一组件在五套主题里极性不同（`Theme.ets:63-82` 的 `nativeTheme` 覆盖 + `theme_colors.json`）。Lead 侧代码核对同结论。
- **现状核验**：**仍存在**（五主题 10-08 才落地）。像素上唯一例外是深色主题里按钮变浅色，视觉尚可，但"主按钮=浅色"的语义仍与蓝色主题冲突。
- **用户影响**：换主题后像换了一套 App；"主按钮在哪"需要重新适应；品牌一致性受损。
- **修法**：主按钮统一为"高饱和 brand 底 + 高对比字"，非蓝主题的 brand 加深（或统一 onAccent 规则）；次要按钮用 tint + accent 文本，并保证与主按钮在明度上至少差一档；色板页补一张"五主题主/次按钮并排"验收图。
- **成本**：M

#### P1-5 首页通栏「花费统计 · ¥0.00」= 零值 + 幽灵按钮，打断首屏节奏
- **严重度**：P1 ｜ **确凿度**：确凿可见 ｜ **与 Lead 笔记 C25/C26 呼应**
- **截图**：`docs/validation/home-phone-restored-api26.png`（02:34，最新手机口径）、`home-wide-start-api26.png` 左列
- **现象**：问候语下方一条通栏浅蓝灰药丸，居中蓝字「花费统计 · ¥0.00」；既没有箭头也没有图标，底色与页面只差一点，像禁用输入框；它夹在问候语和「接下来这份计划」之间，没有分区标题归属。
- **推断原因**：`HomePage.ets:100-114`：`Button('花费统计 · ¥' + expenseTotal(...).toFixed(2))`、`width('100%')`、`backgroundColor(Theme.tint)`、无图标/无 chevron。

- **推断原因**：`Surfaces.ets:27-28`（InteractiveCard：`border 1px + shadow radius12/y3`）vs `:80-82`（EmptyState 仅 shadow radius8）；设置页分组 `shadow radius8` 无描边（`SettingsPage.ets:206-208`）。
- **现状核验**：**仍存在**。
- **修法**：定义 2 档容器（"内容卡 = 描边 + 无阴影；浮层卡 = 阴影 + 无描边"）并全局套用；浅色背景/卡片对比提高一档。
- **成本**：S

#### P2-9 分区标题与正文次级信息同色同重，层级偏平
- **严重度**：P2 ｜ **确凿度**：确凿可见 + 代码确认
- **截图**：`.shots/95-final.jpeg`（接下来这份计划/下一步/最近照片）、`93`、`home-phone-restored-api26.png`
- **现象**：区块标题（「接下来这份计划」「下一步」「最近照片」）15fp、`Theme.muted` 灰，与卡片内 12fp 说明文字同一色系；页面里真正"重"的只有问候语和卡片标题，中间层缺失，扫读时找不到分区边界。
- **推断原因**：`Surfaces.ets:42-55` `SectionHeading` 统一 `15/Medium/muted`；设置页 groupTitle 又是另一套（accent 14 bold）。
- **现状核验**：**仍存在**。
- **修法**：分区标题提为 13–14vp Medium + `Theme.ink`（或加左侧 2px 色条/增大上间距），把 muted 留给辅助文字；设置页与内容页共用同一套分组标题。
- **成本**：S

#### P2-10 浮动 Tab 栏 barOverlap：滚动时内容文字从栏下透出、底行被切
- **严重度**：P2 ｜ **确凿度**：确凿可见 ｜ **设计预期：待复核**
- **截图**：`.shots/95-final.jpeg`（底部「最近照片」被 Tab 栏切掉半行）、`.shots/50-healthy.jpeg`（Tab 栏下透出淡的「Genshin family」）
- **现象**：Tab 栏是悬浮胶囊 + 模糊底，滚动中内容会从栏下方穿出、半行文字被切在栏边；在不滚动时底部内容与栏之间只剩很小间距。
- **推断原因**：`Dashboard.ets:660-666` `barOverlap(true)` + `barFloatingStyle` + `blurStrategy`，页面底部仅 `Blank(bottomInset)`；栏高/内容底部留白没有随栏的实际高度同步。
- **现状核验**：**仍存在**（barOverlap 是当前配置）。
- **修法**：底部 inset 用实际栏高 + 间距（≥ 栏高 + 16vp）；或栏下加更强的模糊/不透明底，避免文字透出。
- **成本**：S

#### P2-11 中英混排与状态标签语义不区分
- **严重度**：P2 ｜ **确凿度**：确凿可见 + 代码确认 ｜ **与 Lead 笔记 B15/C29 呼应**
- **截图**：`.shots/95-final.jpeg`（Tab「Cos」夹在中文之间）、`73-character.jpeg`（「Genshin」）、`70-project.jpeg`（标签「准备中」与「记得确认门票」同色同形）、`41-formsheet.jpeg`（「新建 Cos 计划 / YYYY-MM-DD」）
- **现象**：Tab 与标题里 "Cos"、"Elva Cos" 与中文并列；日期用 `YYYY-MM-DD` 英文占位；状态药丸无论"准备中/门票待确认/已完成"都是同一个 accent-on-tint，全屏只能靠文字读状态。
- **推断原因**：`constants.ets:107` `MAIN_PAGE_TITLES` 里保留 'Cos'；`Surfaces.ets:90-103` StatusPill 无 severity/状态色参数。
- **现状核验**：**仍存在**。
- **修法**：统一术语表（Cos 作品/漫展=活动 二选一 + 中英对照）；日期占位改「选择日期」配合日期选择器；StatusPill 增 `tone`（进行中=accent、需处理=warning、完成=success、结束=muted）。
- **成本**：M

#### P2-12 计划卡缩略图 fallback 是"一个孤零零的大写字母"，像图片加载失败
- **严重度**：P2 ｜ **确凿度**：确凿可见
- **截图**：`.shots/95-final.jpeg`（"Y"）、`93`、`home-phone-restored-api26.png`（"布"）、`73-character.jpeg`（"Y"）
- **现象**：无封面时，76×96 的浅蓝圆角块里居中一个 32fp 细体浅蓝字母，没有幽灵图/相机/人物剪影等"占位"暗示，第一反应是"图裂了"。
- **推断原因**：`ProjectCard.ets:26-39`：`Text(characterName.slice(0,1)).fontSize(32).fontWeight(Lighter).fontColor(accent).backgroundColor(tint)`。
- **现状核验**：**仍存在**。
- **修法**：fallback 用角色剪影/相机占位 icon + 字母小角标；或直接用主题色块 + 图案纹理；字母加重、居中并降低尺寸。
- **成本**：S

## 3. 同屏对比观察

### 3.1 同一设置页：浅色 `81-sky` vs 深色 `90-dark`
- **浅色**：卡片与背景只差一点（白 vs #F6F9FF），主要靠不明显阴影分离 → "糊"；滚动顶栏的玻璃把上层内容虚影直接叠在「设置」标题上（P0-2）。
- **深色**：卡片分离反而更清楚（面性提亮），但**未填充滑轨/次按钮直接消失**（P1-9）；分组图标只剩灰阶，`清空本地数据` 的红色成为唯一彩色强调。
- 结论：浅色缺"边界"，深色缺"控件结构"，两套都还不够稳定。

### 3.2 同一设置页：雾蓝 `80-mist` vs 天蓝 `81-sky`
- 天蓝下选中档位（硬朗/轻柔/天蓝/智感握持）是清晰蓝字，识别 0.2 秒；
- 雾蓝下 accent 去饱和成钢蓝灰，**选中标签与未选标签的灰度接近**，只能靠 300vp 滑轨填充比例判断选中项；"准备中"药丸同样变灰。
- 结论：彩色主题需要单独校一次"选中态/强调文字"对比（旧雾蓝主题已被五色主题替换，但绿/粉/橙主题存在同类风险，需真机对比）。

### 3.3 手机 `home-phone-restored`（378vp 画布）vs 宽屏 `home-wide-start`（920vp 画布）
- 手机：单列 6 区块（问候 → 花费统计条 → 计划卡 → 两按钮 → 下一场活动 → 下一步），首屏信息很长；
- 宽屏：切成 4:6 两栏，但左列**垂直居中悬浮**、右列从顶部开始，两列起点不齐；左栏只有 40% 宽却只放短内容，右栏 60% 挤 3 个区块；
- 宽屏的"固定左概览 + 右侧独立滚动"思路正确，但**对齐和比例**让它看起来像两个页面拼在一起（P1-3）。

### 3.4 旧设置（10-07）vs 新控件参考（10-08 `theme-palettes`）
- 旧版：`应用外观 = 天蓝 / 雾蓝 / 跟随系统` 三档，把"配色"和"浅深色模式"混进一根滑块（语义不成立）；
- 新版：拆成「主题配色（5 色板）+ 应用外观（浅色/深色/跟随系统）」，语义问题已修 —— 这是本次重构里最有效的一处修复。
- 但同一张对照图也暴露 P1-4：五主题下主按钮极性翻转；以及色板行只靠彩色圆点里的白色对勾标选中，五个色点在每行排列相同，辨识成本高。

### 3.5 空白态：旧 `46-events` vs 新 `ui-polish-calendar`
- 同一「漫展/活动」入口：旧版列表空态无按钮，新版改成"列表/日历"分段 + 日历 + 当日活动列表；
- 新版空态 CTA 已补（代码确认），但空态仍顶在内容流上方（P0-3 的布局问题未解决）。

### 3.6 首页两种版本 `95-final`（00:41）vs `home-phone-restored`（02:34）
- 新版在问候语下加了「欢迎来到绮秀」副标题 + 通栏「花费统计 · ¥0.00」按钮；
- 首屏信息更全，但**两个大字级标题（首页标题 + 26fp 问候）之间夹一条幽灵按钮**，节奏更碎（P1-5、P2-9）。

### 3.7 图表在浅色/深色下的观感（仅深色有证据 `ui-polish-expenses`）
- 深色下折线/面积/虚线网格克制、不刺眼，是优点；
- 但 Y 轴无 ¥、X 轴 6 个月只标 3 个、选中详情像页脚（P2-3/4/5），精致度被格式细节拖住。

## 4. 值得保留的优点

1. **HDS 原生外壳方向正确**：原生材质导航、浮动 Tab 栏、DetailDestination 的返回/动效整体观感统一，滚动边效（spring）自然。
2. **浅深色 + 五主题全部资源化**，仓内没有硬编码 hex；主题切换即时生效（`theme-palettes` 对照图可见五套均能跑通）。
3. **卡片按压反馈被统一封装**（缩放 + 光场 + 短振动，`Surfaces.ets:20-34`），且有完整 `accessibilityText/role`；读屏基础比多数个人项目扎实。
4. **空态文案有性格**：「下一场见面，值得期待」「每一张，都是一次登场」「属于你的舞台」——问题只在位置与 CTA，不在文案。
5. **信息结构本身可读**：活动卡（日期/城市/门票）、花费页（大数字 + 预算 + 说明 + 分类占比）、计划卡（状态/角色/进度）都能一眼抓到重点，去掉冗余后潜力很好。
6. **宽屏"固定信息栏 + 独立滚动设置列表"、项目详情"准备/打包/照片"三段式标题栏** 是正确思路，只需修正对齐/比例/极性问题。
