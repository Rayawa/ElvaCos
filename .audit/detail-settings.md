## 1. 一句话结论

「绮秀」的问题不是视觉系统缺位，而是**信息架构和状态反馈没跟上组件质量**：主题、HDS 材质、动效、空态文案已经有体系，但详情页把 5–6 类内容堆成一条长列表、底部动作栏把删除与分享做成同级 Tab、长表单既没有草稿保护也没有字段级错误——这三类问题直接制造困惑、误操作和数据丢失，应先于任何视觉打磨处理。

## 2. P0（阻断级：困惑 / 误操作 / 明显破）

### P0-1 长表单没有任何草稿保护：下滑、点蒙层或返回即静默丢弃已填内容

- **严重度**：P0
- **证据**：`component/FormEditor.ets:62-68`（关闭按钮仅 `busy` 时禁用，无脏检查）、`:344-357`（唯一保存入口固定底部）；`common/sheet.ets:11-23`（统一 `SheetOptions`：`dragBar: true`、`showClose: false`、`onDisappear` 只复位状态，未使用 `shouldDismiss` / `onWillDismiss` 守卫，API 26 的 `SheetOptions` 已提供该字段）；`pages/Dashboard.ets:131-137`（每次 `edit()` 都新建 `EditDraft`，旧输入直接丢失）；`.shots/41-formsheet.jpeg`（LARGE 全高 Sheet、顶部拖动条、右上 X、蒙层，至少 4 条关闭路径）。
- **现象**：活动表单有 12+ 个控件、计划高级设置 6 项、装备 8 个字段，填写过程中任意一次下滑/点蒙层/返回键，Sheet 直接关闭，重新打开只剩空表单；没有「放弃填写？」确认，没有本地草稿，也没有"保存中禁止关闭"。
- **用户影响**：一次误触丢失数分钟输入，且用户会以为已经保存；这是本审计里唯一会直接造成数据丢失的问题。
- **具体修法**：
  1. 在 `appSheetOptions` 增加可选 `guard`，用 `SheetOptions.shouldDismiss` / `onWillDismiss` 统一拦截下滑、蒙层与返回；`EditDraft` 记录打开时的快照，提供 `dirty()`。
  2. dirty 时关闭 → 弹 HDS 确认「放弃本次填写？」（按钮：继续填写 / 放弃，放弃用 `Theme.danger`）；保存中禁止关闭。
  3. 在 `AppStorage`/Preferences 写入 `draft:<kind>:<id>`（不含照片二进制，仅字段），再次打开同一表单时显示「继续上次填写 / 重新填写」；保存成功或明确放弃后清除。
  4. X 按钮与系统关闭路径走同一守卫，避免两套逻辑。
- **成本**：M

### P0-2 底部动作栏把「新增 / 编辑 / 分享 / 删除」做成等权 Tab，危险操作与普通操作并排

- **严重度**：P0
- **证据**：`pages/Dashboard.ets:462-466`（计划 5 项：准备任务 / 从衣柜 / 编辑 / 分享 / **删除计划**）、`:468-470`（角色 4 项，其中「新建计划」「添加版本」都用 `Icons.add`）、`:471-480`（活动 4 项，含删除）、`:481-483`、`:484-498`；`component/HdsActionTabs.ets:23-48`（`HdsTabs` + `BottomTabBarStyle`，全部 `Theme.ink` 同色、`barWidth = min(max(168, items×72), width-32)`、`scrollable(false)`、`onContentWillChange: () => false`，读屏语义是 Tab）；`.shots/70-project.jpeg`、`.shots/30-project.jpeg`（5 项底栏，删除计划在第 5 个）、`.shots/73-character.jpeg`、`.shots/24-character.jpeg`（两个一模一样的「＋」，第 4 项是删除角色）。
- **现象**：底部悬浮条 5 项均分 360vp → 每项约 72vp，「删除计划」4 个字与「从衣柜」同权重；角色页出现两个相同 `+` 图标、无法仅凭图标区分"新建计划/添加版本"；读屏把每个动作念成 tab；默认字号 4 个字约 48–56vp 已接近 72vp；2× 字号约 96vp，固定 72vp 且 `scrollable(false)` 会截断或换行（该形态没有 2× 字号用例，需验证）。
- **用户影响**：删除是常驻可点项，误触概率高（虽有一次确认）；编辑/分享被当成导航去找；大字号用户看到的是被裁切的标签；这是"UI 很糟"最直观的来源之一。
- **具体修法**：
  1. 底栏降为 1 个当前视图主操作 + 1 个「更多」：准备段＝「补任务」、打包段＝「添加物品」、照片段＝「导入照片」；浏览动作与删除都收进「更多」Sheet。
  2. 编辑 / 分享 / 删除移到标题栏菜单（`HdsNavigationMenuItemOptions`，`Dashboard.ets:309-316` 已有空菜单参数），删除项 `Theme.danger` + 与其他项分隔；这与 `UX_RESTRUCTURE_PLAN.md:269` 的「编辑与删除进标题菜单」一致。
  3. 若保留浮动条，改用普通按钮组（`HdsMiniBarButton`/Button + HDS 材质）而非 `HdsTabs`，显式 `accessibilityRole(BUTTON)`，并给出 `maxFontScale` 与截断策略。
  4. 角色页两个 `+` 必须换成语义图标（新建计划＝计划图标、添加版本＝版本/标签图标）。
- **成本**：M

### P0-3 校验失败只有 2 秒全局 toast，字段无错误态、无错误定位

- **严重度**：P0
- **证据**：`component/FormEditor.ets:40-50`（`draft.save()` 返回 false 时只 `reportError`，表单不标记也不滚动）、`:344-356`（保存按钮在底部，长表单错误字段往往在首屏外）；`pages/Dashboard.ets:543-547`（`@Monitor` 里 `showToastSafely(..., 2000)`）；`model/Rules.ets:14-32`（`requiredName`/`moneyToCents`/`safeUrl` 抛通用中文错误）、`model/Schedule.ets:6-30`（日期/时间范围校验）；`component/Surfaces.ets:131-165`（`Field` 只有 label/value，没有 error 参数）。
- **现象**：名称留空保存 → toast「名称需要 1–80 个字」；活动「结束时间应晚于开始时间」不会被标在结束时间上；金额格式错误弹「金额请输入非负数字」；Sheet 保持原状、控件外观无变化、滚动位置不动，错误文案也不带字段名。
- **用户影响**：用户不知道哪一项错，只能逐项猜或放弃；活动/装备这种 10+ 字段表单尤其明显——这是"保存不成功却不知道为什么"的阻断级体验。
- **具体修法**：
  1. `FormEditor` 维护 `@Local errors: Map<string,string>`；保存前先本地校验（把 `Rules`/`Schedule` 的纯校验改成返回错误码并映射字段，或捕获后映射），失败直接定位。
  2. `Field` 增加 `error: string` 参数：字段下方 12vp `Theme.danger` 文案 + 输入框 1vp danger 边框 + `accessibilityDescription(error)`；`Select`/`DateField` 同样有错误容器。
  3. 保存按钮上方显示「还有 N 项待修正」，点击滚动到首个错误；给 Sheet 内 `Scroll` 加 `Scroller` 与字段位置记录。
  4. 文案按字段名改写（"花费用途不能为空""结束时间需晚于 19:00"），toast 只留给系统级失败（空间不足、权限、数据库不可用）。
- **成本**：M

## 3. P1（明显拖累品质）

### P1-1 计划详情「准备」段把 6 类内容堆成一条长列表，没有概览

- **严重度**：P1
- **证据**：`pages/detail/ProjectDetailPage.ets:539-551`（单一 `Scroll`，`section!==1` 时渲染准备/任务/装备/参考图/团队/花费全部内容）、`:217-251`（准备进度卡）、`:253-357`（分类任务）、`:359-398`（本次装备）、`:400-493`（参考图 + 团队 + 实际花费 + 统计入口）、`:396`（「备注」被塞在 `equipmentList()` 末尾）；`.shots/70-project.jpeg`、`.shots/30-project.jpeg`（截图时效：首卡已变，结构未变）；对照 `docs/UX_RESTRUCTURE_PLAN.md:206,250-262`（概览 / 准备 / 打包 / 照片）。
- **现象**：准备段从上到下＝进度卡 → 分类任务 → 本次装备 → 参考图横滑 → 团队分工 → 实际花费 → 查看全部统计；没有概览、卡点区、预算摘要或单一"下一步"；项目备注出现在装备列表之后；参考图和花费属于资料/回顾，不属于准备流程。
- **用户影响**：首屏之后 3–5 屏才能找到团队和花费；用户不知道"现在最该做什么"；长列表让详情像"把表单内容只读展示一遍"而不是工作台。
- **具体修法**：按规格增加「概览」段（计划详情第一段）：日期/关联活动、准备/装备/打包三路摘要（不要合成一个无解释总完成率）、一项「卡点」+ 主动作、预算摘要、团队与参考图摘要行（点击进对应段或子页）；「准备」段只保留分类任务 + 本次装备 + 补任务/从衣柜；备注移入概览；「查看全部花费统计」保留为概览的摘要行入口。
- **成本**：L

### P1-2 角色 / 活动 / 装备详情无分段，且标题栏与正文标题重复

- **严重度**：P1
- **证据**：`pages/Dashboard.ets:333-337`（标题栏 title = 实体名）；`pages/detail/CharacterDetailPage.ets:41-47`（正文又用 20vp 写一次名字）、`:33-39`（1.3 比例封面占满首屏）、`:68-73`（参考图横滑排在版本之前）、`:74-102`（「角色版本 0 个」标题无内容、无空态）、`:103-105`（登场计划）；`.shots/73-character.jpeg`、`.shots/24-character.jpeg`（标题栏 Yoimiya + 正文 Yoimiya 两遍）；`EventDetailPage.ets:69-83`、`AssetDetailPage.ets:33-38` 同样重复；对照 `docs/UX_RESTRUCTURE_PLAN.md:209,303-308`。
- **现象**：三个详情页都是"标题栏实体名 + 正文同名大标题"；角色页封面图占据首屏后，参考图、版本、计划继续纵向堆叠；「角色版本 0 个」下面什么都没有。
- **用户影响**：首屏有效信息只有名字；重复标题让页面看起来没做完；版本区像加载失败；长列表下用户很难快速判断"资料 / 履历 / 参考图"。
- **具体修法**：标题栏保留实体名 → 正文首块改为紧凑 meta 行（作品 · N 个版本 · N 份计划；有封面时把名字叠在封面底部渐变上）；加标题栏分段：角色「资料 / 履历 / 参考图」、活动「概览 / 本场计划 / 提醒」、装备内容短保持单列不分段（`3.8` 反例规则）；版本空态给「＋ 添加版本」行；参考图从版本前移到独立段或资料段摘要。
- **成本**：M

### P1-3 活动详情把提醒 / 设备日历 / 计划全部堆叠，且文案指向错误入口

- **严重度**：P1
- **证据**：`pages/detail/EventDetailPage.ets:85-111`（一个信息卡里放提醒、通知设置按钮、两段设备日历说明、城市、场馆、链接、备注）、`:94-105`（「通知设置」实际打开系统通知设置，提醒时间的设置在编辑表单）、`:106`（设备日历说明）、`:131-146`（本场计划 + 关联已有）、`:144`（「使用标题栏的『新建计划』」——当前「新建计划」实际在底部动作栏 `Dashboard.ets:471-480`）、`:154`（关联 Sheet）；`component/FormEditor.ets:246-254`（提醒时间真正所在）；`.shots/70-project.jpeg` 类推底栏形态。
- **现象**：提醒状态与两个不同系统的入口（系统通知设置、应用编辑表单内的提醒）混在一起；设备日历入口在底部动作栏、说明在信息卡；空计划文案让用户去标题栏找不存在的按钮；没有「提醒」段，权限失败/已建立/时间已过没有独立表达。
- **用户影响**：按提示找不到入口，提醒功能实际不可发现；活动详情成为"说明文字 + 计划列表"两条长内容，缺少"我现在需要做什么"。
- **具体修法**：按 `4.5` 分段「概览 / 本场计划 / 提醒」；提醒段＝应用内提醒开关 + 时间 + 四态状态（未开启 / 已建立 / 权限失败 / 时间已过）+「打开系统通知设置」次级按钮；设备日历改为概览里的次级动作，说明收进「?」popup；修正文案为「底部操作栏的新建计划」或把新建计划移到标题栏菜单；空态 CTA 直接触发新建计划。
- **成本**：M

### P1-4 删除确认不点名对象；删除计划/角色后清空整个返回栈

- **严重度**：P1
- **证据**：`common/Confirm.ets:6-18`（只有 title/message/action，无对象名参数）、`pages/Dashboard.ets:138-161`（所有类型共用「确认删除？」，消息为固定影响描述）、`:154-159`（project/character 删除后 `detailStack.clear()`）、`:162-175`（清空数据/恢复同样单次确认）；对照 `docs/UX_RESTRUCTURE_PLAN.md:186`（删除后只移除失效路由，不能清空全部返回上下文）。
- **现象**：从列表或详情删除时，弹窗里没有任何名称或数量，无法判断删的是哪一条；删除计划/角色后直接回到根页，之前浏览的其他详情路由全丢。
- **用户影响**：误删风险（尤其列表里连续点按）；删除后失去上下文，不知道从哪继续；恢复路径只有重新导航。
- **具体修法**：`confirm` 增加标题参数，删除时生成「删除计划「{name}」？」；message 注入真实数量（N 个清单项 / N 张照片 / N 笔花费）与"系统相册原图保留"；删除成功后只 `pop` 当前失效路由，父对象仍在栈则回父对象，保持 Tab 与筛选；后续再评估"最近删除/撤销 toast"。
- **成本**：S

### P1-5 设置页分组混装：一张卡塞进用户名、振动、材质、主题、外观、操作模式和清除缓存

- **严重度**：P1
- **证据**：`component/SettingsPanel.ets:261-327`（单一 16 圆角卡：`:263` 用户名 → `:274` 振动 → `:294` 材质 → `:305` 主题/外观/操作模式（`PreferenceSettings`）→ `:306` 清除缓存）；`pages/more/SettingsPage.ets:73-78`（分组标题一律 14 Bold `Theme.accent`）、`:273-290`（组名「设置」）；`.shots/74-settings.jpeg`、`.shots/75-slider-drag.jpeg`、`.shots/102-settings-light-icons.jpeg`。
- **现象**：个人资料、触感反馈、外观主题、维护操作在同一张卡内；分组标题「华为账号 / 数据与备份 / 设置 / 帮助」全部用强调蓝，看起来像可点击按钮；「设置」组名在"设置"页内没有信息量。
- **用户影响**：用户找不到「外观」或「存储/数据」；把振动/材质误当外观；清除缓存夹在偏好末尾，像随手可点的开关；分组标题与主按钮抢注意力。
- **具体修法**：拆卡并重命名——「个人资料」（用户名）、「外观与反馈」（主题配色 / 应用外观 / 操作模式 / 振动强度 / 材质等级，可同卡但加 12vp 小标题分「外观」「触感」）、「存储」（缓存大小 / 清除缓存）靠近"数据与备份"；`groupTitle` 改 15vp Medium `Theme.ink`，accent 只给可交互文字；「设置」组改名「外观与交互」。
- **成本**：S

### P1-6 设置里的滑块档位是内部术语，且缺少说明，用户不理解自己在改什么

- **严重度**：P1
- **证据**：`component/SettingsPanel.ets:368-433`（振动强度：关闭 / 灵动 / 硬朗，无说明 popup）、`:490-561`（材质等级：流畅 / 轻柔 / 精美，无说明）；`component/SettingsChoiceSlider.ets:53-88`（应用外观、操作模式同款 190vp 滑块）；对照 `SettingsPanel.ets:82-97`、`:664-668`（用户名和清除缓存反而都有「?」说明）；`.shots/75-slider-drag.jpeg`、`.shots/102-settings-light-icons.jpeg`、`docs/validation/theme-palettes-api26.png`（振动强度/材质等级/应用外观/操作模式四条 190vp 滑块 + 主题配色点选）。
- **现象**：一屏里 4 条几乎一样的轨道；「灵动/硬朗」「流畅/轻柔/精美」是内部命名；材质等级的"流畅＝关闭材质与光效"只写在「使用说明」Sheet 的段落里（`SettingsPage.ets:113`），设置页本身没有解释；滑块没有"低性能设备选流畅"之类的决策帮助。
- **用户影响**：用户不敢动或乱动；改了发现更卡/更吵；这是设置页最容易被评为"看不懂"的部分。

- **现象**：趋势图 y 轴出现 18624 这类读数；窄屏坐标文字降到 10–11vp；环形图不管容器多宽都 200vp；整卡合成一个读屏节点，图例逐项选择对读屏用户可能不可达（需真机验证）。
- **用户影响**：图表在手机/深色下可读性一般；读屏用户只能听到"当前选中的一项"，无法逐项探索。
- **具体修法**：刻度向上取整到 1/2/5×10^n 并带单位；窄屏字号不低于 12vp；分布图 canvas 按容器 180–240 自适应、图例 14vp；图表卡片 `accessibilityGroup(false)`，Canvas 摘要与每个图例分别可读；保留现有空态文案。
- **成本**：S

### P2-7 更新日志筛选状态不可见，若干轻提示文案不一致

- **严重度**：P2
- **证据**：`pages/more/AppLogPage.ets:35-53`（每次筛选 toast 只 500ms）、`:54-67`（标题栏三个纯图标菜单，无文字状态）、`:117-119`（空结果空态）；`EventDetailPage.ets:80`（今天会显示「还有 0 天」，过去显示「已留下的回忆」）、`:144`（"标题栏的『新建计划』"与入口位置不符）；`ExpenseSummaryPage.ets:141-142`（「预计预算」未说明范围）。
- **现象**：切换 Beta/RC/正式版日志后，状态只闪 500ms；标题栏三个相似图标很难看出哪个开着；「还有 0 天」在活动当天读起来奇怪；提示文案和真实入口位置不一致。
- **用户影响**：不知道当前筛了什么；文案让人觉得没校对。
- **具体修法**：更新日志首屏加一行「显示：Beta / RC / 正式版」chips（或菜单项 icon 加勾选语义），toast 只作辅助；统一相对日期表达（今天 / 还有 N 天 / 已结束 N 天）；做一次入口位置与文案的一致性检查。
- **成本**：S

### P2-8 空态缺口：角色版本、花费分类、装备复用计划

- **严重度**：P2
- **证据**：`CharacterDetailPage.ets:74-102`（版本标题在、列表为空时无任何内容）、`ExpenseSummaryPage.ets:65-88`（分类统计无空态）、`AssetDetailPage.ets:58-69`（「复用在这些计划 0 份」下无内容）；做得好的对照：`ProjectDetailPage.ets:508-513`（清单空态 + CTA）、`PhotoDetailPage.ets:44-50`（缺图可补回）、`AppLogPage.ets:117-119`、`DistributionChart.ets:144-145`。
- **现象**：出现 SectionHeading 但无数据时，页面留下孤立标题；部分页面有空态 + CTA，部分完全没有，规则不一致。
- **用户影响**：用户不知道是没数据还是加载失败；没有下一步动作。
- **具体修法**：抽 `SectionEmpty({ title, message, actionLabel, action })` 一行式组件；规则：出现 SectionHeading 必须有空态分支；三处补「＋ 添加版本」「还没有花费，记一笔」「从计划里复用这件装备」。
- **成本**：S

## 5. 值得保留的优点

1. **覆盖式 HDS 详情骨架是对的**：`DetailDestination.ets:36-45` 统一材质标题栏、返回振动与入场；`HdsActionTabs` 用 `onContentWillChange: () => false` 保证操作不替换内容，列表页/详情页各自保留栈（`Dashboard.ets:58-60`）。截图 70/73/74 的页面骨架和返回手势是清楚的。
2. **弹出层结构统一**：`SheetHeader`（标题 + hint + 36vp 关闭）＋ `appSheetOptions`（统一 mask、blur、入场/退出、onDisappear 复位）让所有 Sheet 看起来是一套东西；表单保存按钮固定底部、busy 时变「保存中…」（`FormEditor.ets:344-356`）。新增 Sheet 不需要重新设计。
3. **危险操作的说明文案诚实**：删除计划/照片时明确"系统相册原图保留"、恢复后"缺失图片需重新导入"、照片详情提供"从相册补回"（`Dashboard.ets:140-151`、`ApplicationState.ets:583`、`PhotoDetailPage.ets:44-50`、`ReferenceDetailPage.ets:32`），`Confirm.ets:11-14` 用 danger 色区分确认按钮。这在同类个人应用里不常见。
4. **大屏形态有明确规则且基本成立**：设置页宽屏 4:6 分栏、窄屏单列（`SettingsPage.ets:303-319`），阅读类页面统一 `READING_MAX_WIDTH = 840`；`docs/validation/settings-wide-api26.png`、`settings-narrow-api26.png` 证明布局判断有效。
5. **主题与图表色有体系**：5 组浅深配色、`brand / accent / onAccent / danger` 语义分开（`ThemePalettes.ets:1-16`），图表读取资源色而非硬编码；`docs/validation/theme-palettes-api26.png` 的浅/深对照可读性基本过关，这是后续打磨的现成基础。
